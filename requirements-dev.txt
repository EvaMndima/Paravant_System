# Development Dependencies
#
# Pinned exactly. An unpinned linter is not a quality gate: `ruff>=0.1.0`
# resolved 0.15.0 locally and 0.16.2 in CI, and the newer version's default rule
# set reported 1,013 findings against a tree the older one called clean. A gate
# whose meaning depends on the date of the install cannot be relied on.
#
# The rule set is also declared explicitly in pyproject.toml rather than
# inherited from whatever a given version happens to enable by default.
#
# Upgrading the toolchain is worthwhile and is its own commit: bump the pin,
# run the linter, fix what it finds, review the diff.

# -- Dependency security -----------------------------------------------------
# Queries the PyPI advisory database for known CVEs in the pinned set.
#
# This is the other half of the pinning trade made above. Exact pins remove
# surprise upgrades, which also means a dependency silently stays vulnerable
# until someone looks. Dependabot raises PRs; this fails the build, so a known
# CVE cannot be merged past by ignoring a notification.
