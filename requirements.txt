# Production Dependencies
#
# Pinned exactly, deliberately.
#
# These were `>=` constraints until 2026-08-13, which meant every install
# resolved whatever existed that day. The consequence was not theoretical: CI
# resolved numpy 2.4.6 on the Python 3.11 leg and 2.5.2 on 3.13, a test passed
# on one and failed on the other, and the 3.11 leg is the one the Dockerfile
# deploys. Development, CI and production were running different libraries.
#
# Upgrades are now a deliberate, reviewable commit rather than a side effect of
# when a machine last ran pip.
